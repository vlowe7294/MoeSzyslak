Budgeting System — High-Level Class Design

This document describes the core architecture for a modular budgeting system. It defines the main classes, responsibilities, and relationships that will form the foundation of the budgeting application.

1. Overview

The budgeting system supports:

  • Tracking bank balances
  • Recording income and expenses
  • Managing recurring transactions
  • Automatically generating new transactions based on frequency
  • Providing a foundation for future UI, storage, and reporting layers

2. Class Architecture

2.1 Transaction

Represents a single financial event.

  • Fields: id, amount, date, category, notes, isGenerated
  • Responsibilities: Immutable record of income/expense

// Represents a single financial event
class Transaction {
    int id;
    double amount;
    Date date;
    std::string category;
    std::string notes;
    bool isGenerated;
};

2.2 Account

Represents a bank account or cash pool.

  • Fields: id, name, currentBalance, transactions
  • Responsibilities: Maintain balance and history

class Account {
    int id;
    std::string name;
    double currentBalance;
    std::vector<Transaction> transactions;
};

2.3 RecurringRule

Defines a repeating income or expense.

  • Fields: id, name, amount, frequency, nextDueDate, category, autoApply
  • Responsibilities: Generate transactions when due

enum class Frequency {
    Weekly,
    BiWeekly,
    Monthly,
    Yearly
};

class RecurringRule {
    int id;
    std::string name;
    double amount;
    Frequency frequency;
    Date nextDueDate;
    std::string category;
    bool autoApply;
};

2.4 RecurrenceEngine

Processes recurring rules and generates transactions.


class RecurrenceEngine {
    std::vector<RecurringRule> rules;
};

2.5 BudgetManager

Top-level orchestrator of the budgeting system.


class BudgetManager {
    std::vector<Account> accounts;
    RecurrenceEngine recurrenceEngine;
    Date currentDate;
};
